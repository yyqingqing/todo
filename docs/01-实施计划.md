## 一、已定决策（ADR）

| #   | 决策       | 取值                                        | 影响                                                                |
| --- | ---------- | ------------------------------------------- | ------------------------------------------------------------------- |
| D1  | 悬浮窗形态 | **任意位置置顶窗**（A，非顶部条、非壁纸层） | 不做 Win32 `SetParent`，跨平台成本为 0，节省 2–4 天                 |
| D2  | 桌面壳     | **Electron + React + TS**                   | 环境已就绪，半天出可运行窗口                                        |
| D3  | 周期任务   | **v1 不做**，只做单次任务                   | 无重复规则引擎，顺延逻辑退化为"改日期"，schema 不需要 recurrence 表 |
| D4  | 顺延触发   | **纯手动**                                  | 不写每日定时任务，不需要"自动顺延"设置项                            |

由 D3 + D4 推导出的一个简化：**`task` 与 `todo_item` 严格 1:1**。没有重复任务，一个任务在同一时间只可能排在某一天，因此顺延就是改 `scheduled_date`，不需要复制记录。

| 路由     | React Router v7（data mode） | 主窗口 4 个页面                                                     |

## 四、数据模型（v1 schema 定稿）

日期一律 `TEXT`，格式 `YYYY-MM-DD`（本地日历日）；时间戳一律 UTC ISO 字符串。主键用 ULID（字典序即时间序，对以后同步友好）。

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- 分类：横向维度，平的
CREATE TABLE category (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL UNIQUE,
  color       TEXT NOT NULL,            -- 存 token 名（如 'cat-blue'），不存裸 hex
  sort_order  INTEGER NOT NULL DEFAULT 0,
  archived_at TEXT,
  created_at  TEXT NOT NULL
);

-- 计划：树，可嵌套
CREATE TABLE plan (
  id           TEXT PRIMARY KEY,
  parent_id    TEXT REFERENCES plan(id) ON DELETE CASCADE,
  category_id  TEXT REFERENCES category(id) ON DELETE SET NULL,
  title        TEXT NOT NULL,
  note         TEXT,
  start_date   TEXT NOT NULL,
  end_date     TEXT NOT NULL,
  status       TEXT NOT NULL DEFAULT 'active',   -- active | done | archived
  sort_order   INTEGER NOT NULL DEFAULT 0,
  completed_at TEXT,
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  CHECK (end_date >= start_date)
);
CREATE INDEX idx_plan_parent ON plan(parent_id);
CREATE INDEX idx_plan_range  ON plan(start_date, end_date);

-- 任务：计划的叶子，必须归属一个计划
CREATE TABLE task (
  id          TEXT PRIMARY KEY,
  plan_id     TEXT NOT NULL REFERENCES plan(id) ON DELETE CASCADE,
  title       TEXT NOT NULL,
  note        TEXT,
  est_minutes INTEGER,
  status      TEXT NOT NULL DEFAULT 'open',      -- open | archived（放弃）
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_task_plan ON task(plan_id);

-- 每日待办：task 在某天的实例。临时事项 task_id 为 NULL
CREATE TABLE todo_item (
  id             TEXT PRIMARY KEY,
  task_id        TEXT UNIQUE REFERENCES task(id) ON DELETE SET NULL,  -- UNIQUE 保证 1:1，同时允许 NULL
  title          TEXT NOT NULL,                  -- 快照，孤儿记录靠它显示
  scheduled_date TEXT NOT NULL,
  origin_date    TEXT NOT NULL,                  -- 首次排期日，顺延不改它
  status         TEXT NOT NULL DEFAULT 'pending',-- pending | done | dropped
  completed_at   TEXT,
  rollover_count INTEGER NOT NULL DEFAULT 0,
  sort_order     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);
CREATE INDEX idx_todo_date ON todo_item(scheduled_date, status);
CREATE INDEX idx_todo_task ON todo_item(task_id);

-- 顺延留痕
CREATE TABLE rollover_log (
  id           TEXT PRIMARY KEY,
  todo_item_id TEXT NOT NULL REFERENCES todo_item(id) ON DELETE CASCADE,
  from_date    TEXT NOT NULL,
  to_date      TEXT NOT NULL,
  created_at   TEXT NOT NULL
);
CREATE INDEX idx_rollover_item ON rollover_log(todo_item_id);

-- 积分流水：append-only，可冲正，不改不删
CREATE TABLE score_ledger (
  id           TEXT PRIMARY KEY,
  event_id     TEXT NOT NULL UNIQUE,   -- 客户端幂等键（防双击/重试重复入账）
  unique_key   TEXT UNIQUE,            -- 一次性事件业务键，如 'plan_done:<id>'；普通流水为 NULL
  source_type  TEXT NOT NULL,          -- todo | plan | daily | streak
  source_id    TEXT NOT NULL,
  reason       TEXT NOT NULL,          -- todo_done | todo_late | plan_done | daily_clear | streak_7 | revoke
  points       INTEGER NOT NULL,       -- 允许负数（冲正）
  occurred_at  TEXT NOT NULL,          -- 事件实际发生时间（UTC）
  settled_date TEXT NOT NULL,          -- 入账日（本地日期），用于日/周/月榜
  meta         TEXT,                   -- JSON 快照：当时的标题、计划名等
  created_at   TEXT NOT NULL
);
CREATE INDEX idx_score_date ON score_ledger(settled_date);
CREATE INDEX idx_score_src  ON score_ledger(source_type, source_id);

CREATE TABLE setting (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                  -- JSON
);

CREATE TABLE schema_version (
  version    INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL
);
```

### 几个建模决定及原因

**1. `todo_item.task_id` 同时 UNIQUE 和可空。** UNIQUE 保证一个任务只对应一条待办（D3 无重复任务，所以成立）；SQLite 允许多个 NULL，所以临时事项不受限制。任务被删时 `SET NULL` 让记录变成孤儿，但 `title` 快照还在，历史不会变成空白。

**2. 完成态只存在 `todo_item` 上，`task` 没有 done 状态。** 避免"任务已完成"和"某个待办已完成"两套语义打架。计划完成度通过 join 派生，不冗余存储。

**3. `origin_date` 与 `scheduled_date` 分离。** 这是需求 7 留痕的实现基础，也是"平均拖延天数""按时完成率"两个指标的唯一数据来源。

**4. `score_ledger` 分两类幂等。**
- 状态派生型（勾/取消勾）：每次状态变更写一条，`event_id` 防重复提交，靠 `points` 正负抵消，`unique_key` 为 NULL。
- 一次性成就型（计划完成 / 每日全清 / 连续 7 天）：`unique_key` 填业务键，唯一索引保证只发一次奖。

这个设计同时解决了"勾选→取消→再勾选不能加两次分"——它不是靠禁止，而是靠净额抵消，账本始终可追溯。

## 五、关键业务规则（写在 `shared/domain/`，全部可单测）

### 完成度

```
计划完成度 = 该计划及其所有后代计划下的 task 中 status='done_todo' 的数量
             ÷ 同类 total（排除 task.status='archived'）
```
"done_todo" 指存在 `todo_item.status='done'`。父计划不单独加权，只做汇总——避免出现"父 50% + 子 50% = 75%"这种没法解释的数字。

### 积分规则（默认值，存 settings 可改）

| 事件      | reason        | 分值      | 触发条件                                                |
| --------- | ------------- | --------- | ------------------------------------------------------- |
| 当天完成  | `todo_done`   | +10       | `scheduled_date == 完成日`                              |
| 逾期完成  | `todo_late`   | +6        | `scheduled_date < 完成日`                               |
| 取消完成  | `revoke_todo` | −(原分值) | 勾选被撤销，冲正                                        |
| 当日全清  | `daily_clear` | +20       | 当日 pending 归零且总数 ≥3                              |
| 计划完成  | `plan_done`   | +80       | 手动确认完成，`unique_key='plan_done:<id>'`             |
| 连续 7 天 | `streak_7`    | +50       | `unique_key='streak_7:<date>'`，同一 streak 每 7 天一次 |

### 顺延

```
rollover(todoId, targetDate):
  断言 status='pending'
  更新 scheduled_date = targetDate, rollover_count += 1
  插入 rollover_log(from, to)
  不改 origin_date —— 它是历史
  触发目标日的"今日"刷新
```
批量顺延走同一函数，包在一个事务里。

### 放弃

`todo_item.status='dropped'`，同时把关联 `task.status='archived'`。放弃不扣分（心理上要允许体面退出），但不计入完成度分母。

## 六、IPC 契约

`shared/ipc-contract.ts` 定义一个 `Api` 类型，preload 用 `contextBridge` 映射，主进程注册同名 handler。渲染进程只 `import type { Api }`。

```ts
interface Api {
  // 查询
  category: { list(): Promise<Category[]>; upsert(c): Promise<Category>; remove(id): Promise<void> }
  plan: {
    tree(): Promise<PlanNode[]>
    detail(id): Promise<PlanDetail>
    save(p): Promise<Plan>
    remove(id): Promise<void>
    complete(id): Promise<void>
  }
  task: { listByPlan(planId): Promise<Task[]>; save(t): Promise<Task>; archive(id): Promise<void> }
  todo: {
    byDate(d): Promise<TodoItem[]>
    range(a, b): Promise<TodoItem[]>
    create(input): Promise<TodoItem>
    update(id, patch): Promise<TodoItem>
  }
  // 有副作用的命令（主进程负责事务 + 积分 + 广播）
  action: {
    complete(id, eventId): Promise<TodoItem>
    uncomplete(id, eventId): Promise<TodoItem>
    rollover(ids: string[], targetDate): Promise<void>
    drop(id): Promise<void>
    reorder(ids: string[]): Promise<void>
  }
  calendar: { month(year, month): Promise<MonthView> }
  score: { ledger(page, size): Promise<LedgerPage>; summary(range): Promise<ScoreSummary> }
  overlay: {
    show(): void
    hide(): void
    setClickThrough(on: boolean): void
    getState(): Promise<OverlayState>
    setBounds(b): Promise<void>
  }
  onDataChanged(cb: (entity: string) => void): () => void
}
```

**同步策略**：所有写操作完成后，主进程向**所有窗口**广播 `data:changed`，携带实体名。渲染进程用 TanStack Query 的 `invalidateQueries` 精确失效。这是两个窗口数据不一致的唯一防线，必须一开始就做对。

### 阶段 0 实际遇到的环境问题（都已写进 README）

这几条不在原计划里，但会直接卡住后来的人，所以记下来：
1. **pnpm 12 的配置位置变了。** `onlyBuiltDependencies` / `neverBuiltDependencies` 合并成了 `allowBuilds` map，且只认 `pnpm-workspace.yaml`。写在 `.npmrc` 或 `package.json#pnpm` 里会被**静默忽略**——不报错，也不生效，最难排查。同理 `nodeLinker` 也搬到了 `pnpm-workspace.yaml`（所以上面 R1 里"在 .npmrc 设 node-linker"的写法对 pnpm 12 是无效的，已修正）。
2. **TypeScript 7 移除了 `baseUrl`。** `paths` 必须写相对路径（`./src/shared/*`），否则 `tsc` 直接 TS5102 失败。
3. **Electron 45 不再自带 postinstall。** npm 包里的 `scripts` 字段是空的，二进制要靠 `install-electron` 显式触发。已用 `scripts/ensure-electron.mjs` 包成幂等的 postinstall。
4. **`ELECTRON_RUN_AS_NODE=1` 会让 Electron 退化成纯 Node。** 表现为 `require('electron')` 返回一个路径字符串而不是 `{ app }`，报错 `Cannot read properties of undefined (reading 'isPackaged')`。某些 IDE / 终端会带这个变量。

另外一条经验：**高 DPI 下不要用 PowerShell 桌面截屏做视觉自检。** `CopyFromScreen` 在非 DPI 感知进程里会截偏，我因此一度误判"空状态组件没渲染"——实际 DOM 和布局都正常，是截图错了。已改为 Playwright 直接驱动 Electron（`pnpm shot`），拿的是页面而不是屏幕，顺带也不会截到用户其它窗口。
