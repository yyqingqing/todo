  不需要依赖心跳兜底。

## 三、已知限制（有意为之，不是 bug）

| 限制                           | 原因                                                               |
| ------------------------------ | ------------------------------------------------------------------ |
| 强杀 / 断电最多丢 15 秒        | 心跳间隔 15 秒。再密没有收益，再疏丢得更多                         |
| 会话不可编辑、不能补记         | S3 的决定：只认用户点「开始」，避免手填数据污染统计                |
| 统计按**当前**本地时区解释历史 | 出差换时区后同一批数据的"日期"会变。项目全局约定：日期用本地日历日 |
| 悬浮球只吸附左右边缘           | 上/下边在窄屏上会和任务栏、窗口标题栏抢位置，先不做                |
| 长时间挂机会如实记录           | 不做自动截断，只做 4 小时提醒——不替用户改数据                      |

## 五、远期目标：目标栏（Markdown 笔记）

> 2026-10-30 评估后暂缓。以下调研结论直接可用，重启时不必重做选型。

**需求**：新增「目标」页，左文件列表 + 右所见即所得 Markdown 编辑区（类似 Typora），
用来写目标、心得、三年计划这类自由文本。

**编辑器选型：Milkdown**（已实测包体积）

| 方案                  | 体积                                      | Markdown 存储     | 结论                              |
| --------------------- | ----------------------------------------- | ----------------- | --------------------------------- |
| **Milkdown**          | ~400 KB（core 191 + react 100 + presets） | 原生，基于 remark | 选它                              |
| TipTap                | ~1.1 MB（react 574 + markdown 482）       | 需额外序列化      | 功能强但重，Markdown 不是第一公民 |
| Vditor                | 23 MB                                     | 是                | 太重                              |
| CodeMirror + 预览分栏 | ~150 KB                                   | 是                | 不是所见即所得                    |

选 Milkdown 的决定性理由：**存储格式就是 Markdown 源文**，将来能直接导出、
用别的工具打开，不被锁在 ProseMirror 的 JSON 里。且与现有 `remark-gfm` 生态一致。

**数据模型**（当时已写好迁移，回滚了）：

```sql
CREATE TABLE goal_doc (
  id         TEXT PRIMARY KEY,
  title      TEXT NOT NULL,
  content    TEXT NOT NULL DEFAULT '',   -- Markdown 源文
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_goal_sort ON goal_doc(sort_order);
```

**已定的交互**（评估时确认过）：扁平列表（不做父子文件夹）、停止输入 800ms 自动保存、
无置顶/最近编辑排序。界面与「计划」页同构（左列表 + 右详情），不引入第二套布局。

**开工前必须先验证**：Milkdown 在**中文输入法**下的表现——拼音组合过程中
若光标跳位或重复上屏，这个编辑器就不能用。这一步没做，是暂缓的原因之一。
